# Instruction: Add Japanese Card Name Display Support

## Goal

Extend the existing MTGA Draft Helper (based on MTGA_Draft_17Lands or its forks)  
to support **Japanese card name display**, using an existing **English ↔ Japanese card name mapping JSON**.

The feature must allow users to **toggle between English and Japanese card names** in the UI.

---

## Assumptions

- A JSON file exists that maps English card names to Japanese card names.
  - Example structure:
    ```json
    {
      "Lightning Strike": "稲妻の一撃",
      "Sheoldred, the Apocalypse": "黙示録、シェオルドレッド"
    }
    ```
- Internally, all card identification continues to use **English card names** (as provided by MTGA logs / 17Lands).
- The Japanese display is **purely a presentation-layer feature**.

---

## Required Features

### 1. Language Toggle (UI)

Add a language switch that allows the user to choose:

- `EN` (default)
- `JP`

#### Requirements
- The toggle should be easily accessible (e.g. top bar / settings panel).
- The selected language should be persisted (e.g. `localStorage`).
- Changing the toggle should immediately update card name display without reload.

---

### 2. Card Name Conversion Logic

Implement a centralized card name resolver.

#### Function Signature (example)

function getDisplayCardName(englishName: string): string
Behavior
If language is EN → return englishName
If language is JP:
Look up the English name in the JSON mapping
If found → return Japanese name
If not found → fallback to englishName
Notes
Do not mutate the original card data.
Conversion should happen only at render time.

### 3. Injection Points (Where to Apply)
Replace direct usage of card.name (or equivalent) in UI rendering with the resolver:
Typical targets
Draft pick list (current pack display)
Suggested picks / ranking list
Deck list preview
Tooltip / hover card name text
Logs or overlays that show card names
Example
// before
<span>{card.name}</span>

// after
<span>{getDisplayCardName(card.name)}</span>

### 4. State Management
Language setting should be stored in a global or shared state
Example: React Context / global store / simple module state
The resolver must reference this state to determine current language.

### 5. Performance Considerations
Load the English–Japanese mapping JSON once at startup.
Use in-memory lookup (object / Map).
Avoid repeated JSON parsing or fetch calls.
6. Error Handling & Fallback
Missing Japanese entries must not break rendering.
Always fallback safely to English.
Optionally log missing mappings for later improvement.
Non-Goals (Explicitly Out of Scope)
No changes to draft logic, scoring, or statistics.
No modification of 17Lands data ingestion.
No automatic translation or API-based translation.
No changes to MTGA log parsing.
Expected Result
Users can switch between English and Japanese card names seamlessly.
Draft recommendations and rankings remain identical.
Only the displayed card names change.
Optional Enhancements (Future)
Language auto-detection based on browser locale
Partial language mode (JP name + EN subtitle)
Mapping validation tool to detect missing cards
